# PanSou 搜索结果元数据说明

## 为什么过去会出现空白或 0 分？

原融合版 `server/api/pansou/search.post.ts` 把所有结果的 `fileSize`、`resolution`、`videoCodec`、`audioCodec` 设置为空，并把 `rating` 固定为 0。前端又直接按照 MoviCloud 的标准资源信息格式显示，造成数据丢失或错误的评分暗示。

PanSou 的 `merged_by_type` 主要有链接、提取码、`note`、来源、时间等；它不是网盘文件元数据或媒体探测 API。无法仅凭搜索接口验证媒体文件大小、编码、分辨率，也没有资源用户评分的可靠字段。

## 当前修复范围

- 从 PanSou 的 `note`（资源标题/说明）中尽可能提取大小（GB/TB 等）、分辨率（720P/1080P/4K 等）和部分音视频编码关键词。
- 界面把上述值明确标注为“标题推断”，可能不准确；未知项显示“未知”。
- 不再把 PanSou 搜索结果的评分伪装为 0.0；统一显示“暂无资源评分”。
- 不改变网盘搜索、跳转和转存逻辑。

## 尚不支持

- 网盘分享目录里每个文件的真实大小与媒体技术参数，需要对接各网盘的文件列表接口，必要时借助媒体探测工具获取真实编码。
- PanSou 的资源评分，不能等同于 TMDB 的影视作品评分。电影详情页的 TMDB 评分与具体网盘资源评分是两类数据。
- 对多文件分享链接，标题上的大小和编码不能代表分享目录中的每个文件。

## 如何验证

1. `git pull --ff-only origin main` 获取最新源码。
2. 从干净的 MoviCloud 1.0.6 构建工作树重新运行补丁应用脚本，避免覆盖当前运行版本。
3. 使用 `npm run build:fnOS` 和项目的 `scripts/pack-fnos.sh` 重新打包（会生成一个新的 FPK 和新的 SHA-256）。
4. 在测试环境安装，分别检查含“4K H265”等信息的搜索结果与无相关信息的结果，确认前者显示“标题推断”、后者显示“未知”。
5. 回归测试电影、电视剧搜索及夸克/UC 转存。
